# 视觉任务截图验收方法

本方法用于首页、组件、动画、主题、图标、画布与排版等视觉任务。目标是让修改以可复现的截图和明确验收标准为依据，而非仅凭代码推断效果。

## 适用规则

视觉变更必须先明确目标状态、参考图或可核验的文字目标，再建立包含真实内容的最小场景。截图中不得用占位素材替代待验证的真实内容；空态、加载态、静止态、悬停态和展开态须按需求分别验证。涉及桌面窗口的截图只能在沙箱外运行。

每轮修改遵循“基线截图 → 观察差异 → 单一假设 → 小范围修改 → 同条件复拍 → 结论记录”的闭环。不要同时改动无关尺寸、颜色、动画和结构，否则无法判断是哪项改动带来改善或回归。

## 可复现流程

1. 明确状态与环境：记录窗口尺寸、系统缩放、主题、数据内容、交互状态和等待时长。默认至少检查 Windows 100% 与 150% 缩放、明暗主题，以及静止和触发交互后的稳定帧；涉及动画时，还应截取开始后的早期帧、中间帧和稳定帧。
2. 构造最小真实场景：使用测试夹具或临时项目导入真实图片、视频、文本等素材；首页、卡片和缩略图必须来自实际项目内容。需要固定数据时写入现有预览脚本或测试夹具，并在脚本注释说明来源和目的。
3. 生成基线：在沙箱外构建后运行对应截图脚本。当前首页使用 `node scripts/preview-home.mjs`，可设置 `WORKBENCH_DEVICE_SCALE_FACTOR=1.5` 核对 150% 缩放。截图只写入忽略提交的 `test-results/`。
4. 对照观察：并排查看目标与截图，按下列顺序记录可见差异：布局和比例、内容可见性、层级与遮挡、色彩和透明度、边缘/圆角/阴影、文字可读性、动画结束位置与运动路径。描述应使用可行动的事实，例如“前玻璃覆层遮住文件上缘”“内页仅露出 0 px”，避免“看起来不对”。
5. 提出单一假设并修改：每次只针对一个或一组直接相关参数调整，例如降低前片遮罩和模糊、提高文件栈静止抬升量。保留响应式尺寸、真实数据绑定、键盘操作和减少动态效果设置，避免为了截图硬编码数据或破坏交互。
6. 在相同环境复拍：等待动画完成后截取同名状态，和基线、目标逐项比较。若效果仍不符合预期，重复步骤 4–6；达到标准后再扩大到其他主题、缩放和边界内容场景。
7. 回归和记录：运行覆盖受影响行为的最小测试及构建；视觉脚本需要真实启动 Electron 时在沙箱外执行。把实现、依据和验收结果补充到功能对应的 change-log 条目，避免按时间堆积截图流水账。

## 验收标准

### 布局与层级

- 主体尺寸、留白、对齐和圆角与参考一致；不同缩放下不发生裁切、重叠或滚动条抖动。
- 前景、内容和背景的 z-index 关系清楚。需要“装在容器内”的元素保留可辨认边缘；需要遮挡时不得泄露不应出现的内容。
- 空态仅显示空态，真实内容出现后才渲染对应预览；不得用虚构卡片填充画面。

### 材质、色彩与可读性

- 玻璃、遮罩和模糊既保留材质感，也保留需求指定的内容辨识度。检查内容图像、标题和元数据在常规对比度下是否可见。
- 明暗主题使用各自 Token；不把截图中的显示色当作唯一权威值。涉及近似色时保留权威色值及换算说明。
- 阴影、描边、高光和透明度在 100% 与 150% 缩放下连续自然，无明显锯齿、脏边或过度泛白/泛黑。

### 动画与交互

- 截取静止态、悬停/聚焦态、展开态的动画稳定帧；核对起止位置、持续时间、散开方向、层级和可点击区域。
- 键盘聚焦、鼠标离开与关闭状态保持可用；“强制播放动画”关闭时遵循系统的减少动态效果设置，开启时在该系统设置下仍须按预期播放。视觉优化不得吞掉按钮、文件项或辅助功能语义。

## 判定与交付

满足全部目标项、所有指定状态均无可见回归、截图脚本可重跑且相关构建/测试通过，才可标为“已验证”。若缺少参考图或目标无法量化，记录当前假设、截图证据和待人工确认的具体差异，不把主观判断写成已验收结论。
